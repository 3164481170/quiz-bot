# quiz-bot —— 网页 AI 答题程序

读取网页上的题目 → 调用**你自己接入的 API** 生成答案 → 自动填回输入框。

提供两种形态，按需选一种即可：

| 方案 | 形态 | 适用场景 | 推荐度 |
| --- | --- | --- | --- |
| **A. 油猴脚本** | `userscript/quizbot.user.js` | 在浏览器里答题（普通网页、问卷、在线考试） | ⭐ **推荐** |
| B. 桌面程序 | `main.py` | 客户端软件、无法注入 JS 的窗口 | 备选 |

如果你的答题界面就是浏览器页面，**直接用方案 A**，无需安装 Python、无需开调试端口。

> **先判断你的界面属于哪种形态：**
>
> - 页面上一堆单选框 / 输入框 / 下拉框 → 用**表单模式**（面板下面那组按钮）
> - 页面像一个聊天窗口，智能体发题、你在底部输入框回复 → 用**对话模式**（面板上面那组按钮，见下方专门章节）

## 方案 A：油猴脚本（推荐）

### 为什么推荐它

因为脚本运行在**页面内部**，可以直接读写真实 DOM：

- 不需要截图、不需要图像识别 —— 题目文字是直接从 DOM 读的，**准确率 100%**
- 不需要开浏览器调试端口，不需要重启浏览器
- 不需要 Python、不需要管理员权限
- 兼容 React / Vue 等框架（用原生 value setter + 派发 input/change 事件，框架能正常感知）
- API Key 只存在你自己的浏览器里（Tampermonkey 存储），不经过任何第三方

### 安装

1. 给浏览器装 [Tampermonkey](https://www.tampermonkey.net/)（篡改猴）扩展。
2. 打开 Tampermonkey → 「添加新脚本」，把 `userscript/quizbot.user.js` 的**全部内容**粘贴进去，Ctrl+S 保存。
   （也可以直接把 `.user.js` 文件拖进浏览器窗口，Tampermonkey 会弹出安装确认。）
3. 打开你的答题页面，右下角会出现蓝色圆形「AI」按钮。

### 使用

1. 点圆形按钮展开面板 → 点「**设置**」，填写你的 API：

   | 字段 | 说明 |
   | --- | --- |
   | 接口类型 | 大多数情况选 `OpenAI 兼容` |
   | Base URL | 例如 `https://api.openai.com/v1`（**末尾不要带** `/chat/completions`） |
   | API Key | 你的密钥（只保存在本地浏览器） |
   | 模型名 | 例如 `gpt-4o-mini` |

2. 点「**测试连接**」，看到「连接成功 ✔」说明配置无误。
3. 点「**读取题目**」，日志里会列出识别到的每道题 —— **务必先确认题目抓全了、抓对了**。
4. 点「**AI 作答并填写**」，脚本会自动调用 API、解析答案、填入页面。

### 答题记录

面板上的「**📋 答题记录**」会列出处理过的每一道题，最新在最上面：

```
✔ [10:22:03] 【单选题】(2分)：下列哪一个选项不属于 Java 基本数据类型的关键字？
      → A
○ [10:22:41] 这是一条闲聊
      → 无需作答
✗ [10:23:10] 【判断题】(2分)：Java 表达式 3 + 2 * 2 的运算结果是 10
      → 出错未发送

共 3 条记录
```

标记含义：

| 标记 | 含义 |
| --- | --- |
| ✔ | 已作答并发送成功 |
| ○ | 模型判断无需作答（闲聊/通知） |
| ✗ | 出错未发送（接口报错等），该题之后仍会重试 |

> 「记录」只是**留痕**，不会阻止作答。同一道题再次出现时仍会正常作答。

**记录会持久保存**：写入 Tampermonkey 存储（没有 Tampermonkey 时用 localStorage），
刷新页面、关闭浏览器后都还在，最多保存 500 条。重复出现的题会标注 `⟲ 第 N 次出现`。

作答时日志会明确告诉你这道题是不是以前见过：

```
⚠ 这道题以前出现过（本次是第 3 次），上次答案：B，时间：2026/10/18 11:52:50
最新题面（38 字）：「【单选题】(2分)：下列哪个不是基本类型？ A: int；B: String」
```

新题则显示 `✓ 这是一道新题`（在「① 预览对话」里可见）。

点「**📤 导出记录**」可以导出成 Markdown 文件，含完整题面、答案和说明，方便事后复习。

### 面板上的其它按钮

- **仅按上次答案填写**：不重新调用 API，用上一次的答案重填（改错了想重来很有用）
- **清空日志**：清掉日志区
- **收起**：把面板缩成圆形按钮，不挡视线

### 控制台模式（不装 Tampermonkey）

把整个脚本内容粘到浏览器控制台（F12）回车也能用，此时：

- 配置存在 `localStorage` 而不是 Tampermonkey 存储
- **要求你的 API 支持浏览器跨域调用（CORS）**；如果报跨域错误，还是建议装 Tampermonkey

### 脚本提供的 JS 接口

装好后 `window.quizbot` 可用，方便你写自动化或调试：

```js
quizbot.read()      // 读取题目，返回数组（不调用 API）
quizbot.run()       // 完整流程：读题 -> 调 API -> 填写；返回 Promise<{okCount, fails, total}>
quizbot.fill()      // 用上次答案重新填写
quizbot.questions() // 查看上次读到的题目
quizbot.answers()   // 查看上次的答案
quizbot.config      // 当前配置对象
quizbot.save({...}) // 修改配置
```

### 支持的题型

- **单选题**（radio）
- **多选题**（checkbox）
- **判断题**：选项是 `对/错`、`是/否`、`T/F`、`正确/错误` 都能匹配
- **填空题 / 简答题**（input、textarea）
- **下拉选择题**（select）

题干和选项从 DOM 提取，自动剥掉「A. 」「1. 」这类前缀；选项 key 优先用页面上真实的字母标记，没有就退回 `value` 或 `A/B/C` 顺序。

### 常见问题

**Q：识别到的题目数量不对 / 漏题？**
先点「读取题目」看日志。如果题目在**跨域 iframe** 里，脚本读不到（浏览器安全限制）—— 把那个 iframe 的网址单独在新标签页打开再跑脚本。

**Q：填了但页面没反应 / 提交时是空的？**
脚本已经用原生 setter + 派发 `input`/`change` 事件来兼容 React/Vue。如果某个网站用了特殊的富文本编辑器（如自研的 contenteditable），需要手动补一条规则，可以在 `fillOne()` 里扩展。

**Q：API 报错？**
先点「测试连接」。常见原因：Base URL 多写了 `/chat/completions`、模型名不对、Key 过期、账户余额不足。日志区会显示具体的 HTTP 状态码和返回内容。

**Q：会不会误提交？**
自动提交**默认关闭**。要开启需要先在设置里填「自动提交按钮文字」并勾选「自动提交」。建议先用 `--dry-run` 思路：只点「读取题目」+ 手动确认答案，全部满意后再开自动提交。

## 方案 B：桌面程序（Python）

当目标**不是普通网页**（例如客户端软件内嵌的答题窗口、无法注入 JS 的页面）时使用。

### 两种工作模式

| mode | 原理 | 适用 |
| --- | --- | --- |
| `cdp` | 通过 Chrome DevTools Protocol 读真实 DOM 并填写 | 浏览器网页 |
| `vision` | 截屏 → 多模态模型读题+给坐标 → 模拟鼠标键盘 | 任意窗口 |

### 安装与使用

```powershell
python -m pip install -r requirements.txt
python main.py --list-windows    # 列出可见窗口，用于填写配置
python main.py --probe           # 只识别题目并打印
python main.py --dry-run         # 识别 + 作答，但不写入页面
python main.py                   # 正式填写
```

CDP 模式需要浏览器带调试端口启动（必须先**完全退出**浏览器）：

```powershell
& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" ``` 
    --remote-debugging-port=9222 --user-data-dir="C:\edge-debug"
```

配置见 `config.example.json`（复制为 `config.json` 后修改）。

## 更新记录

**v1.9.1**
- 修复：**设置面板在小屏 / 系统缩放较大时显示不全且无法滚动**。
  面板原先是固定 `bottom:16px` 且没有高度上限，内容一多就向上溢出视口顶部，
  超出部分既看不到也点不到。现在：
  - `max-height: calc(100vh - 32px)` —— 高度永远不超过可视区域
  - `overflow-y: auto` —— 内容超出时出现纵向滚动条，可滚动查看全部设置项
  - `max-width: calc(100vw - 32px)` —— 窄屏不再横向超出
  - `box-sizing: border-box` —— padding 不会把面板撑出边界
  - `overscroll-behavior: contain` —— 滚到底不会带动网页本身滚动
- 结构快照弹窗同样改为受视口约束（`max-height: calc(100vh - 32px)`、宽度上限、border-box）
- 新增 `tests/ui-scroll.test.mjs`：锁死上述样式约束（13 项）

**v1.7.1**
- 修复：**自动应答偶尔中断**。一次挂住的请求会让忙标志永久为 true，
  之后所有题目都被「正在处理上一条消息」挡掉。现在有三重保护：

  现在出错**不登记**，下一轮会自动重试
- 修复：**处理期间到达的新题被丢弃**。现在会记下「有待处理」，忙完立刻补一次
- 保持「每次只答最新一道」的语义（平台每次只出一道题），不去翻历史旧题重答
- 新增 `tests/auto-answer-resilience.test.mjs`：复现并锁死上述问题（9 项）

**v1.7.0（重要）**
- 修复：**「识别到 1 条消息」且是已答过的旧题** —— 结构驱动（先找"消息列表"那一层再取最后一条）
  在真实平台上很不稳：消息区可能虚拟滚动、只渲染可视项、或把新旧消息放在不同容器里。
  现在改为**内容驱动**：扫描所有同源文档里的文本块，挑出「像题目且非批改反馈」的**最后一条**，
  完全不依赖消息列表的 DOM 层级。
- 修复：**开了自动应答却毫无反应**。此前 MutationObserver 只挂在消息列表节点上，
  而新题常常渲染到别的容器（甚至另一个文档）里，于是永远收不到通知。
  现在监听**所有同源文档的 body**，任何变化都会重新判断有没有新题目。
- 修复：**去重失效导致重复回答旧题**。此前最新题答完后会「回退」去找更早的未答题并重答；
  现在只看最新那一道，已答过就安静等待新题。同时用 `handledHashes` 记录已作答题面。
- 开启自动应答时会**立即检查一次**（开启时页面上可能就已经有待答题目）
- 「🔄 重置识别」会同时清空「已作答」记录，便于重新测试
- 新增 `tests/auto-answer.test.mjs`：复刻真实消息流，验证选题／去重／自动应答／列表外新题（12 项）

**v1.6.0（重要）**
- 修复：**挑错了要回答的消息**。答题流程的消息流是「题目 → 我作答 → 批改反馈 → 下一题」，
  旧逻辑只取「最后一条对方发的消息」，于是选中了**批改反馈**（「你的回答是…本题得分…」），
  模型正确地判断「无需作答」并跳过 —— 表现为一直不作答。
  - 新增内容判别：识别**批改反馈**（你的回答是／正确答案／本题得分／错因分析／反馈）并排除
  - 识别**题目**（【单选题】等题型标记、第N题、1. 序号、≥2 个选项行、以问号结尾）
  - 选择顺序：最后一条「像题目」的消息 → 退化为最后一条「对方发的、非反馈」消息 →
    都不满足时明确报告「没有待答题目」并**不发起 API 请求**
- 预览时会标注每条消息的类型：`[对方/题目]`、`[对方/批改反馈]`、`[我/其他]`，
  并说明「待回答（依据：…）」，一眼就能看出选得对不对
- 区域模式同样应用该判别，遇到反馈直接跳过
- 新增 `tests/pick-question.test.mjs`：复刻真实消息流验证选题（10 项）

## 让作者帮你写精准适配（推荐！）

### 为什么不是「把网址发给我」？

因为我看不了：

- 我没有你的账号密码（也不该向你索要）
- 我的网页抓取工具**不执行 JavaScript、不带登录态**，扣子这类应用抓回来只是个 JS 空壳

但等价的事完全可以做 —— 把**渲染后的真实 DOM 结构导出**给我。这比我"自己去看"更准。

### 操作：两步，一分钟（不用控制台）

1. 打开你的答题页面，点右下角「**AI**」展开面板
2. 点绿底的「**📋 导出结构快照（发给作者）**」

页面右上角会出现一个文本框，点「**复制**」（或「下载为文件」）。

> ⚠️ **不要用 F12 控制台粘贴**：Chrome 默认拦截控制台粘贴（防诈骗），
> 会要求你先输入「允许粘贴」才能执行。直接点面板按钮最省事。
> 如果你更习惯控制台：`tools/snapshot.js` 仍然可用，但需先在控制台输入「允许粘贴」并回车。

### 强烈建议：再点一下「点击采集某个气泡」

点了之后，**去点一下智能体发的那条题目气泡**。它会额外采集那个元素的完整祖先链和 HTML，
这是最有价值的信息 —— 有了它我基本能一次写对。

## 识别不出来怎么办（两把兜底武器）

自动识别靠猜 DOM 结构。页面越特殊（无意义类名、超深嵌套、iframe 内嵌），越可能失败。
这时**不要跟它较劲**，直接用下面两种**不依赖猜测**的方法。

面板上标着 ★ 的那排按钮就是。

### 方法一：点一条消息学会它 ⭐ 最推荐

点「**点一条消息学会它**」，然后**点一下页面上任意一条消息气泡**（智能体发的那条）。

脚本会从你点的位置往上推断："什么样的一组元素构成了消息列表"，并记住这个特征。
比全页猜测精确得多，而且它认的是**消息的长相**，所以之后新来的消息也能认出。

日志会立刻列出识别到的每条消息和 [对方] / [我] 标记 —— 直接就能看出成功没有。

### 方法二：框选题目区域

点「**框选题目区域**」，按住左键**拖一个框框住题目文字**（像截图那样）。

这种方法**完全按几何位置取文字**，不看任何 class 和 DOM 层级 —— 只要文字是真实 DOM 文本，
就一定能读到。框选后：

| 按钮 | 作用 |
| --- | --- |
| 区域模式：答最新 | 把框内最新一道题发给 AI 并回复 |
| 区域模式：自动应答 | 持续监听，内容一变就自动作答 |

框选范围会被记住（同一网址下次打开自动恢复）。

**框选技巧**：框住**整段聊天记录**即可，脚本会自动切出**最后一道题**
（认得「第一题：」「1.」「【判断题】」等题号格式）。只想答某一道题，就单独框住那一道。

> 框选时请**避开底部的输入框和发送按钮**。脚本会自动剥掉控件文字，但框得干净些更保险。

### ★ 答题界面在 iframe 里？（扣子就是这种情况）

**这是最常见的原因。** 很多平台（含**扣子 coze.cn**）把整个答题界面放在一个 iframe 里：

- 顶层文档只有空壳（页面顶部那条面包屑、以及本脚本的面板）
- 真正的对话区、输入框、题目全在 iframe 内部
- 脚本在顶层查找时"什么都看不到"，表现为**识别不到**，或者**指定了也没用**
  （点在 iframe 上时，父文档只能拿到 `<iframe>` 元素本身，它是没有文字的）

**v1.5.0 已完整支持 iframe**：脚本会穿透所有**同源可读**的 iframe，在那里读题目、写输入框、点发送。

具体做了这些事：

| 环节 | 处理方式 |
| --- | --- |
| 查找元素 | 递归遍历顶层 + 所有同源 iframe 文档 |
| 坐标 | 累加 iframe 偏移，换算到统一的顶层视口坐标 |
| 事件 | 用**元素自己所在文档**的 `MouseEvent/KeyboardEvent`（跨 realm 才有效） |
| 写值 | 用元素自己文档的原型 setter，React 才能感知 |
| 面板 | 只在顶层显示一个，不会在每个 iframe 里重复出现 |

> 跨域 iframe（不同域名）受浏览器安全限制，**任何脚本都读不到**，这是无法绕过的。
> 遇到这种情况，请把该 iframe 的网址单独在新标签页打开，再运行脚本。

### 实在都不行？

用 `tools/diagnose.js` 把页面结构打出来发我：

1. 打开答题页面 → F12 → 「控制台 / Console」
2. 把 `tools/diagnose.js` 全文粘贴进去，回车
3. 把输出整段发回来

它只读不写，会报告：是否在 iframe 里、所有候选输入框、候选消息容器、Shadow DOM、屏幕采样点等。

## 对话模式（答题界面是「和 AI 智能体对话」的窗口）

有些答题平台的界面**不是问卷表单**，而是一个聊天窗口：智能体在左侧气泡里发题（比如「【判断题】(2分)：Java 中所有的关键字都不能作为标识符使用　A: 正确；B: 错误」），你需要**在底部输入框里打字回复**。

这种界面要用**对话模式**，不能用表单模式 —— 表单模式会去扫页面上的输入框，结果只会把底部的聊天输入框误当成一道填空题。

### 三步走

面板上用这组按钮：

| 按钮 | 作用 |
| --- | --- |
| **① 预览对话** | 读出聊天气泡并打印，**先确认它到底读没读到、谁发的** |
| **② 回答最新一条** | 取最新一条「对方」的消息 → 问 AI → 写进输入框 → 自动发送 |
| **③ 自动应答 开/关** | 开启后持续监听，智能体每发一条新题就自动作答回复 |
| 指定消息区域 | 自动识别不准时，手动点选聊天气泡所在的容器 |
| 指定输入框 | 自动识别不准时，手动点选底部输入框 |

**推荐先用 ① 确认识别结果，再用 ② 试一次，最后才开 ③ 自动应答。**

### 它是怎么读到消息的

聊天界面千差万别（Coze、扣子、自研系统各不相同），所以脚本用**结构性启发式**而不是写死选择器：

1. **找消息层级**：在容器里逐层扫描，找出「多条重复兄弟节点、且每条都接近叶子节点（文字密度高）」的那一层 —— 那就是消息列表。
2. **区分谁发的**：优先看 class / `data-role` 等语义线索（`self`、`me`、`ai`、`bot`…）；看不出来就看**位置**，靠右的通常是「我」，靠左的是「对方」。
3. **找输入框**：优先 `contenteditable`，其次 `textarea`，并结合是否位于消息列表下方、附近有没有「发送」按钮来打分。
4. **写入**：富文本输入框用 `execCommand("insertText")`，普通输入框用原生 value setter + 派发 `input`/`change`，两种方式框架都能感知。
5. **发送**：优先点「发送」按钮，找不到就发回车键事件。

### 如果方向判断反了

在「设置 → 对话模式」里把**「我的消息位置」**从「自动判断」改成「我的消息在左侧」或「我的消息在右侧」。

### 安全阀

- **回复延迟**（默认 1500ms）：检测到新消息后等一会儿再回复
- **每分钟最多回复**（默认 12 条）：超过就自动停止应答，防止刷屏或死循环
- **自动应答默认关闭**，必须手动开启

### 控制台接口

```js
quizbot.chat.preview()      // 预览识别到的消息 [{text, self}]
quizbot.chat.answer(true)   // 回答最新一条（true = 忽略去重）→ Promise
quizbot.chat.start()        // 开启自动应答
quizbot.chat.stop()         // 停止自动应答
quizbot.chat.detect()       // 重新自动识别消息区域与输入框
quizbot.chat.messages()     // 读取当前消息列表
quizbot.chat.pickList()     // 进入点选模式，手动指定消息区域
quizbot.chat.pickInput()    // 进入点选模式，手动指定输入框
```

### 对话模式的常见问题

**Q：预览时一条消息都读不到？**
点「指定消息区域」，直接点选**装着聊天气泡的那个容器**（不是整页，也不是单个气泡）。选完会立刻重新预览。

自动识别采用「从输入框往上找 + 按消息条数打分」的策略，并会自动排除侧边栏会话列表和输入区。
若页面结构特殊导致识别失败，手动指定一次即可，选择会被记住（下次打开自动生效）。

**Q：自动应答跑着跑着就不动了？**
v1.7.1 已修复。根因是一次请求挂住后忙标志没有释放，后续题目全被挡掉。现在有看门狗兜底：
卡住超过 90 秒强制恢复，并按指数退避重试（日志会显示「看门狗：作答卡住…已恢复」）。
接口报错时也不再登记为已作答，下一轮会自动重试。

**Q：开启自动应答后毫无反应？**
v1.7.0 已修复。此前监听只挂在「消息列表」节点上，而新题常常渲染到别的容器里，
于是收不到任何通知。现在监听所有同源文档，任何变化都会重新判断有无新题目；
开启时还会立即检查一次。日志会显示「已开启自动应答：监听 N 个文档」。

**Q：日志显示「识别到 1 条消息」而且总是同一条旧题？**
v1.7.0 已修复。这是结构驱动的固有问题（消息区虚拟滚动／只渲染可视项／新旧消息在不同容器）。
现在选题改为**内容驱动**：直接扫描文本，找出最后一道「像题目且不是批改反馈」的内容，
与消息列表的 DOM 层级无关。

**Q：日志显示「模型判断这条无需作答，已跳过」，一直不答题？**
v1.6.0 已修复。答题的消息流是「题目 → 我作答 → **批改反馈** → 下一题」，
而批改反馈（「你的回答是…正确答案…本题得分…」）也是"对方发的"，
旧逻辑按"最后一条对方消息"取，就取到了反馈。模型判断它不需要作答是**正确的**。

现在会先做内容判别：批改反馈被排除，只挑真正像题目的消息。
点「① 预览对话」时每条消息都会标注类型，例如：

```
#1 [对方/其他] 郑靖禹同学，刚才的《AI 编程工具与高效开发》测试题：
#2 [对方/题目] 【判断题】(2分)：Java 中所有的关键字都不能作为标识符使用 A: 正确；B: 错误
#3 [我/其他] a
#4 [对方/批改反馈] 你的回答是：a正确答案：A…本题得分：2
#5 [对方/题目] 【单选题】(2分)：执行代码 int a = 7; a = a * 2; 后变量 a 的值是？
→ 待回答（依据：含题目标记）：「…【单选题】…」
```

看到 `→ 待回答` 指向的确实是当前那道题，就可以放心开自动应答了。

**Q：识别到的内容是页面顶部的面包屑（如「商店 / 学习教育 / …」）？**
v1.5.1 已修复。原因是之前某次「指定消息区域」误选了顶部面包屑，该选择被保存下来，
之后每次打开都优先使用它。现在保存的选择器会先经过「内容是否真像聊天记录」校验，
不合格会自动丢弃并重新识别；面包屑/标题栏/工具栏也会被明确否决。

如果仍看到旧行为，点面板上的「**🔄 重置识别**」，一键清空所有已保存的选择，然后重新点「① 预览对话」。

**Q：框选区域明明有文字，却提示「框内无文字」？**

若仍失败，日志会自动给出诊断（是否滚出视口、采样点命中了什么元素），把它发我即可。

**Q：点按钮后页面卡住 / 转圈？**
v1.2.0 已修复。此前版本会对页面上每个容器做全子树扫描，每次扫描又强制浏览器同步重排，
在大页面上足以冻结主线程数十秒。现在所有几何读取都走**同帧缓存**，并带**硬预算**
（超过 4000 次测量或 1.2 秒即收手），任何页面都不会再卡死。
如仍遇到卡顿，请把页面地址和日志发我。

**Q：能读到消息，但「回答最新一条」说自己找不到对方消息？**
说明方向判断反了。去设置里手动指定「我的消息位置」。

**Q：答完没有发出去？**
看日志里的「已发送（方式：…）」。如果显示点了按钮却没反应，可能是该网站的发送按钮不在输入框附近，点「指定输入框」重选一次；也可以手动按回车。

**Q：会不会把闲聊也答了？**
脚本会先让模型判断这条消息**是否包含需要作答的题目**，不包含就返回 skip 跳过（日志会显示「模型判断这条无需作答，已跳过」）。
